# 连接锁定回归检查

2026-10-24：用例源码扩展为按已连接设备操作，覆盖手机目标、锁定转移后的其他设备状态、未知状态及离线目标。新用例本轮未执行；下方历史实测记录不能视为跨设备版本验收。

```powershell
dotnet run --project probe/LockChecks/LockChecks.csproj --configuration Release
```

链接真实的模型、协议编解码器和数据源；替换 WinUI 类型、Windows 蓝牙发现、RFCOMM 传输和音频端点枚举，因此不会操作实际蓝牙或音频设备。40 项检查覆盖帧与真机抓包一致、字段缺失/未知、非本机/断开目标、幂等写入、回读不一致、链路丢失及绑定状态更新。

未连接提示页新增检查：启动不接触耳机；区分蓝牙关闭、耳机未连接与适配器不可用；未连接时不打开 RFCOMM；恢复连接后显示控制页；断开后隐藏旧电量/设备控件并禁止操作。页面视觉效果和真实系统开关切换由用户手动验收，测试不会关闭蓝牙或发送真实锁定指令。

回归复现解锁后连接状态返回 3 的情况：保持已连接和有效锁状态，不出现底部成功提示，仍不接受未观察过的状态 4。新增检查要求修改请求确认到达后才能发出查询，确认缺失或拒绝时不冒充成功、不重发；音频输出从有到无时暂停读取。锁定完成后不会再于 2 秒自动重开 SPP。测试将生产环境的同会话 1.2 秒等待设为 0，仅验证处理顺序；不能据此判定固件/驱动播放稳定性。
