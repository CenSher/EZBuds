# FreeBuds 7i 降噪无法开启：当前排查状态

用户确认添加强度下拉框之前可以开启降噪，新增强度后不能正常开启。下文保留诊断阶段的证据；后续用户反馈及映射修正见末尾。诊断包本身没有修改降噪行为。

## 已有证据

- `releases/7i-mode-fix-20261025/startup-error.log`：09:36:47 发送 Cancellation，未收到独立 ACK，随后两次查询均返回 Off/0。
- 同一会话 09:36:52 透传有 ACK 且回读 Awareness/2；09:36:54 关闭有 ACK 且回读 Off/0。说明当前问题不只是界面没有更新，也不能简单归为整个通道失效。
- 用户确认的旧版为添加强度之前。`peer-lock-20261024` 的源码快照已与 BUILD_INFO 哈希核对；旧版和新版的开启降噪参数均为 `01 FF`，HuaweiProtocol 与 BluetoothNative 源码哈希相同。
- 上游 HuaweiPods 固定提交 `115f080100c07fb51174b3238473c512a2c6d3b8` 的 `HuaweiHfpController.kt/huaweiAncCommandSubMode` 在主模式变化时使用 FF。不能只根据 `defaultAncSubMode` 就断言应改为直接发具体强度；完整模式入口还包含这一转换。

## 当前修改

只增加用户主动切换期间的诊断日志：记录实际构造的降噪 TX 完整帧，以及 2B04 / 2B2A / 2B03 的 RX 字段；其他通知仅记录命令编号。不修改现有报文，不增加写入重试，不自动切换设备或耳机模式。

诊断包：`releases/anc-trace-20261025/EZBuds.exe`；独立入口 `启动EZBuds降噪诊断.cmd`。普通启动入口不替换。仅编译，没有运行测试或启动应用。
