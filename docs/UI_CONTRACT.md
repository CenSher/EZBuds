# 桌面行为与交付约定

这些是用户已确认的产品要求。修改窗口、阴影、材质、动画、导航、启动入口和托盘时，都必须保持；只有用户明确更改要求时才能调整。

1. **普通启动只显示托盘图标**：首次启动、重复启动、`--background` 和旧 `--show` 均不展开菜单。`--settings` 只额外打开设置。发布入口不带预览或常驻菜单参数。
2. **菜单失焦自动收回**：使用当前前台窗口判断，不能只依赖可能遗漏的激活事件。重复显示同一面板、关闭右键菜单、关闭确认气泡、托盘恢复后仍要继续跟踪。`--preview` 不关闭自动收回；只有显式调试参数 `--keep-open` 才可关闭。
3. **整块阴影与透明材质**：阴影不能取样菜单文字、图片、电量条或移到屏幕外的 XAML 元素。当前使用九宫格阴影 PNG，中心完全透明，12 DIP 外部绘制区，32 DIP 九宫格边界；明暗主题分别为 0.22/0.30，不在亚克力下方铺实色层。高对比度关闭阴影。
4. **标题是一个点击区域**：设备名和紧随其后的箭头共用一个按钮和提示 `[设备名称](点击以切换)`；鼠标悬浮无单独边框，键盘焦点反馈保留。
5. **不使用 Computer Use**：用户负责界面和耳机实机测试；代码检查、编译和资产检查不能写成“阴影/自动收回已实测通过”。
6. **抽象文案的悬浮提示**：开启抽象文案时，华为耳机固定为“已连接到WAWEI耳机”，荣耀耳机固定为“已连接到Honor耳机”；随当前型号品牌切换。关闭抽象文案时，提示与正常显示文字一致，即“已连接到华为耳机”或“已连接到荣耀耳机”。

## 每次交付

- 先运行 `tools/check-ui-contract.ps1`；构建入口也必须调用它。失败时不发布。
- 并行修改同一工作区时，使用独立源码快照和独立输出目录构建，避免共享 obj/bin 和半写入资源。记录构建文件与源码 SHA256。
- 正常入口无调试参数；历史版本留作回退，不能将旧版文件混进新包。更新统一的根目录启动入口。
- 发布记录分开列出代码/资产检查、编译，以及用户手动验收状态。用户验收前标记为“待界面验收”，不能称为稳定通过。
- 交给用户的最小回归：默认冷启动、重复启动、外部点击自动收回、重复开合、切换页往返、浅深主题和 DPI 下四边阴影、整个标题点击与提示。

## CodeGraph 的作用

项目有 `.codegraph/` 时，先用它追踪 App → ShellWindow → PopupSurface/PopupAnimation → EarphonePanel 的关系和修改影响。没有索引时不自动创建。
CodeGraph 提供代码关系和源代码定位，不提供像素、显卡合成或真实焦点行为的验收结论；不能替代上述检查与用户验收。
