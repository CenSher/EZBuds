# FreeClip 2 按设备连接锁定

## 界面与操作

- FreeClip 2 设备列表仅对已锁定的连接追加“已锁定”。未锁定或锁定字段未知时不追加标注；未知状态仍通过禁用操作和按钮提示处理，不视为未锁定。
- 展开设备卡片后显示锁按钮；只有连接状态明确、仍连接、锁定字段有效时允许点击。未知字段不当作未锁定。
- 确认框显示目标设备名称。本机额外标记“本机”，不再将所有目标都写成“这台电脑”。
- 锁定新目标会转移已有锁定，不能把多副连接都当作独立、可同时生效的锁。不会为操作离线设备而自动连接它。
- 只对 FreeClip 2 的已适配锁定流程开放；其他耳机型号不因此获得锁定能力。

## 协议与确认

已有设备表查询 `0x2B31` 的每一行都读取 TLV `0x0D`：单字节 0 为未锁定、1 为已锁定，其他值或字段缺失为未知。本次主要移除了界面和操作权限中的“仅本机”限制，没有新增猜测的命令。

命令仍为 `0x2B33`：锁定使用参数 8，解锁使用参数 9，值直接采用最新设备表 TLV 4 的六字节原始目标地址，不重新编码显示地址。每次用户确认至多写入一次，等待对应 ACK、在同一会话内等待固件稳定后回读；不因不确定结果自动重发。

确认锁定成功需要完整设备表、目标仍连接且锁定为真，同时其他设备状态可解释、其他已连接设备锁定为假。确认解锁需要完整回读且目标仍连接、锁定为假。应答成功、目标按钮变化均不能替代回读。

原有 Windows 音频端点诊断仅用于本机目标；主动把锁定转移给手机时，不用本机音频端点变化否定远端状态。链路丢失、缺少确认等保留原有暂停自动读取和提示路径。

## 依据与边界

- 华为[固定出声通道说明](https://consumer.huawei.com/cn/support/content/zh-cn16103564/)说明可通过手机 App 指定电脑等连接设备，并说明给另一设备加锁会解除原锁定。
- 本地已捕获官方手机 App 对电脑目标的锁定流量，以及 Windows 客户端的锁定、解锁回读：`.scratch/audio-lock-incident-20261022-1105/phone-protocol-timeline.json`、`.scratch/connection-lock-on-20261022-102721.json`、`.scratch/connection-lock-off-20261022-102822.json`。
- 电脑向手机/平板目标施加、解除锁定属于本次代码扩展，未做本机跨设备实测。历史上已有官方 App 和桌面客户端锁定电脑后音频异常的记录，见 [诊断记录](../probe/LOCK_AUDIO_FAILURE.md)；本次不声称解决了该固件/驱动稳定性问题。
- 按用户要求仅编译与源码约定检查。回归用例源码同步了目标地址、锁定转移、未知状态和断开设备的边界，但未执行测试程序、未启动应用、未向耳机发送命令。
